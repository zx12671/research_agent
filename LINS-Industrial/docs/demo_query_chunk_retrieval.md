# 活体演示：真实 query ↔ chunk 检索全过程（代理）· 2026-08-08

> 触发：澄清"agentic 项目中真实的 query 与 chunks 如何工作、检索时 chunks 检索其什么、问题与 chunks 的关系"。
> 方法：真实 `OpenDomainRetriever.hybrid_retrieve`（`retrieval/retriever.py`）+ 2 条真实 CSV 问题，
>       全确定性、零 LLM；脚本 `_demo_retrieve_live.py` / `_demo_retrieve_verify.py`。

## 1. 一句话机制
建库时把 55095 个知识块 `content` 用 `bge-small-zh-v1.5` 编码成 512 维向量存进 FAISS（flat/IP）；
查询时把问题做 **KED 扩展 → multi-query 拆分 → 每路 dense**，再叠 **BM25 稀疏**，最后 **RRF 融合**出 top-k；
`chunk_id` 回查 `industrybench_chunks.jsonl` 拿原文 + `capability/industry` 元数据，包装成 `RetrievedChunk` 喂下游。

## 2. 数据规模（manifest.json / 运行时）
- `total_documents=2048, total_chunks=55095`
- `embedding_model=bge-small(zh-v1.5, dim=512, cpu)`, `index_type=flat`
- 运行时加载：`[INFO] 已加载 55095 个块元数据`；BM25 索引 `54809 篇chunk`。

## 3. 两条真实问题的完整检索链路

### q1：6RA70 选型并联（capability=选型与替代）
```
原始 query : 在冶金轧机这类高负载工艺中，若需超过单台SIMOREG DC Master 6RA70装置的输出能力，应采取何种运行方式来满足需求？
KED 扩展   : …（原文）+ 关键词[在冶金轧机这类高负载工艺, SIMOREG, RA70, 6RA, DC]
multi-query: 拆为 3 子查询（场景 / 装置能力 / 运行方式）
参考答案(CSV): 采用多台装置整流并联运行。
```
| rank | score | chunk_id | capability | content 开头 |
|---|---|---|---|---|
| 1 | 0.0197 | 3f3d53d2895b | 选型与替代 | SIMOREG DC Master 6RA70 系列是一类全数字化直流调速装置… |
| 2 | 0.0193 | 0407bcb09d4e | 选型与替代 | SIMOREG DC Master 6RA70 系列在运行过程中包含带危险电压… |
| 3 | 0.0189 | 543223557407 | 选型与替代 | 整流单元型谱涵盖600 A… |

**命中判定（精细口径）**：`chunk 3f3d53d2895b`（rank1）原文
`…稳定驱动各类中、大型直流电机。当多台装置采用整流并联运行时，其输出能力可进一步叠加，满足…`
→ **「多台装置 / 整流并联 / 输出能力叠加」三要点全部在 rank1 chunk 内，召回命中且排第一**。（✓）
top10 的 capability：`{选型与替代, 工艺原理与参数影响, 标准规范与术语}` —— 型号命中主轴是「选型与替代」。

### q2：高杆照明 5.2.3.4（capability=安全合规与风险控制）
```
原始 query : 在升降式高杆照明装置中，若采用单根主钢丝绳作为升降系统的上绳，除需满足设计安全系数不小于8外，还应设置哪些安全装置以防止灯盘意外坠落？
multi-query: 拆为 4 子查询
参考答案(CSV): 应设置防止灯盘意外坠落制动装置或自动卸载装置。
```
| rank | score | chunk_id | capability | content 开头 |
|---|---|---|---|---|
| 1 | 0.0195 | 763d672c630b | 安全合规与风险控制 | 在实际组装完成的升降式高杆照明装置…定型样品的防止灯盘意外坠落制动… |

| 3 | 0.0191 | bc45b2c0410f | 安全合规与风险控制 | `### 5.2.3.3 升降系统上绳采用单根钢丝绳时，其钢丝绳设计安全系数不小于 8…` |

**命中判定**：`chunk 00007b44eb7b`（rank2）即**标准条款 5.2.3.4 原文**，与参考答案几乎逐字一致

top10 capability **100% 集中在「安全合规与风险控制」** —— 主题聚焦极强。

## 4. 结论（对照前面的 S4 归因）
- 这两条真实问题的**召回都命中**（q1 答案在 rank1、q2 标准条款在 rank2），
  dense(型号/标准号) + BM25 + multi-query 融合在"主题明确"的长问上工作良好。
- 因此 **"query 与 chunk 在同一向量空间做相似度匹配"是这两例正确的检索机制**；
  问题与 chunk 的关系 = 语义相似 + 词面(BM25)双通道，再按 chunk 元数据归位到能力域。

## 5. 口径修正记录
- 第一版 `_demo_retrieve_live.py` 曾对 q1 打印"✗ 未命中"，系**判定 bug**：
  其逻辑按「，」切答案后要求整段逐字出现，而真实 chunk 措辞是「…当多台装置采用整流并联运行…」
  （字序不同）→ 误判。
  精细版 `_demo_retrieve_verify.py` 用关键短语「多台装置 / 整流并联 / 自动卸载」判定，得到正确命中结论。
  → 结论以**精细版为准**；第一版脚本的"✗"输出不具判定效力。
- 附带启示：**判定召回命中应比"答案实体/要点"而非整段字面，否则会像第一版那样把命中误判成漏检**——
  这正对应 S6 那轮「实体正确但表述不同不应判低」的教训。
