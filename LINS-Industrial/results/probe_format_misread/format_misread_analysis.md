# 格式改写增益探针 — 量测结论

## 判定项
- 假设：格式身份(标准号/版本号)在原文中不可独立检索 → 检索拉不回源 chunk → 是 format×capability 低召回的主因。
- 若成立，则"改写查询(反解析 doc_id + 内容头)"应显著高于"原文字面查询"的 hit。

## 实测(真实 DeepSeek-chat + hybrid_retrieve, k=10)
| 指标 | 值 |
|---|---|
| 随机采样编号型文档(含标准号/版本号) | 24 个 chunk |
| **原文字面查询(raw_q=内容头) hit@1** | **24/24 (100%)** |
| 改写查询(DeepSeek 反解析) hit@1 | 23/24 (96%) |
| 纯新增(仅改写命中、原文miss) | **0** |

## 结论 / 修正
1. **样本 chunk 完全可检索**：当查询接近原文措辞时，混合检索 100% 拉回源 chunk。**源文档/片段并非检索不可达**。
2. **改写不带来增益 (纯新增=0)**：故"格式身份无法检索"这一假设 **不成立**——
   真正的瓶颈不在「chunk 不可检索」，而在「**真实用户问题的措辞与标答的 format 身份无显式关联**」：
   - 真实题目描述的是任务/场景/参数，而 format(标准号串) 是标注元数据，两者在语义空间中不属于同分布；
   - 因此按 format 求值(query=format 串)天然低命中(见交叉矩阵: format 单维命中率低且取值分散)，
     而按内容 query(近原文) 命中率极高。

## 与交叉矩阵(先前行)的整合
- capability 主轴 hit≈63%：内容语义检索有效。
- format 单维/交叉差：由「format 标注与问题措辞语义失配」造成，非检索器失效。
- 熔断：无需检索前"格式改写"；应把 format 当作**条件性二级过滤/展示字段**，
  而非检索主轴；当 capability 命中后，再按 format 值交集过滤。

## 局限
- 本探针样本为自检索校验(raw_q 取 source chunk 内容头)，用于验证"chunk 可达性上限=100%"这一上界，
  不模拟真实问题措辞；真实措辞失配已由 153 题 format×capability 交叉矩阵覆盖。
